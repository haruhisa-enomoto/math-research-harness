# Worked session: conversation to checkpoint

This fictional walkthrough shows how ordinary conversation drives the harness.
It contains no substantive research claim.

## 1. Catch up

Owner:

> Catch up on the sample inquiry and tell me what you want to do.

Agent behavior:

1. Read `AGENTS.md`.
2. Read `threads/sample-inquiry/LEDGER.md`.
3. Follow only the claim or note links needed to assess the proposed direction.
4. Explain the present boundary and propose one useful investigation.
5. Wait before beginning sustained research.

## 2. Begin a directed investigation

Owner:

> The proposed boundary test sounds worthwhile. Go for it.

Agent behavior:

1. Treat the proposal as the authorized scope.
2. Create disposable work under
   `.research-scratch/sample-inquiry/<session>/`.
3. Try the promising route, repair it when useful, and test a discriminating
   example rather than stopping at the first failed step.
4. Return when there is a result, precise obstruction, owner-dependent pivot,
   or clearly diminishing expected value.

## 3. Distinguish progress from resolution

Suppose the agent settles only setting S while the unrestricted target remains
open. The agent reports exactly that. The restricted result may become a durable
claim, but it does not complete the unrestricted target.

Likewise, a finite check or an equivalent reformulation is labeled with its
actual scope rather than presented as a solution.

## 4. Record a coherent package

When the result becomes durable, the agent:

1. obtains the timestamp from the operating system;
2. writes one coherent note under `threads/sample-inquiry/notes/`;
3. adds an exact claim to `CLAIMS.md` if it is independently reusable;
4. updates the ledger only with the changed present-facing consequence;
5. runs the repository check; and
6. commits the package and canonical changes together.

The sample result in this repository illustrates that checkpoint.

## 5. Owner feedback changes the right layer

- “Record this as progress” marks significance but does not upgrade evidence.
- “I checked this proof” may upgrade that exact claim to
  `proved/owner-checked`.
- “Pivot” redirects the route while preserving genuine results or obstructions.
- “Put this in the report” authorizes report writing; it does not alter the
  research claim.

The owner speaks naturally. The agent translates those instructions into the
appropriate repository mechanics.

## 6. When the route needs literature

Suppose a related result may already be known. The agent reads
`docs/LITERATURE.md`, checks the local catalog, and then performs focused public
discovery. Finding a promising title is only discovery; it does not establish
the fictional claim.

Before recording `proved/literature`, the agent completes a source check using
`templates/SOURCE-CHECK.md`: exact statement, assumptions, conventions, version,
and a checkable locator. If the source proves only setting S, the unrestricted
target remains open. The durable note cites the verified source check, while the
ledger records only its present-facing consequence.

## 7. When the route needs computation

Suppose a finite test can distinguish two proposed mechanisms. The agent first
uses `.research-scratch/` to test whether the calculation is informative. If the
result becomes durable, it moves the one-off program to
`experiments/sample-inquiry/`, the machine-readable output to
`data/sample-inquiry/`, and the explanation to `results/sample-inquiry/`.

The summary records the exact command, backend and versions, conventions,
finite scope, and remaining limitation. A positive finite pattern remains
`verified-computationally` at that scope. A refuting witness also receives a
small certificate verifier and a mathematical note explaining why it is a
counterexample.

## 8. When collaboration helps

The lead agent may assign independent, nonconflicting tasks to internal
subagents—for example a proof attempt and a source check. The lead compares and
audits their returns and alone updates the ledger and commits.

For a collaborator without repository access, the lead fills in
`briefings/templates/OUTBOUND.md` from canonical state. The response is preserved
with `briefings/templates/INBOUND.md` and remains correspondence until its
load-bearing claims have been checked and absorbed through an ordinary research
note.
